# 주제 → 블로그·카드뉴스·숏츠

인자로 주제 문장이나 `/topics` 후보 번호를 받는다. CLAUDE.md의 원칙, 디자인, 스펙 형식을 따른다. 예시는 `content/01-ai-dangjik/`이다.

## 1. 회차 폴더
- `content/`의 마지막 번호에 1을 더하고 영문 슬러그를 붙인다. 예: `02-voice-deepfake`
- 브랜치는 `content/NN-slug`로 만든다.

## 2. 사실 확인 (서브에이전트)
- 기사 속 숫자, 날짜, 명칭을 1차 출처로 교차 검증한다.
- 결과는 CONFIRMED / DIFFERENT / NOT FOUND 표로 받는다.
- NOT FOUND인 내용은 쓰지 않는다. DIFFERENT는 고친 값으로 쓴다.
- 기사에 공급 업체 이름이 나오면 기록만 하고 본문에는 쓰지 않는다.

## 3. blog.md (원본)
- 분량: 1,500~2,500자(공백 포함)
- 제목: 검색 노출용으로 핵심 키워드를 앞에 둔다.
- 첫 문단: 인용(>)으로 쓴 요약 2문장
- 소제목(##) 4~6개. 순서: 뉴스 → 방식/의미 → 확산·인사이트 → 라피치(같은 흐름의 별개 사례) → 마무리 → `## 출처`
- 분량 비율은 뉴스 6 : 라피치 4

## 4. spec.json (슬라이드)
- 블로그를 9장 안팎으로 압축한다. 순서: 표지 → 뉴스 3~4장 → 인사이트 1장 → 라피치 2~3장 → 마무리
- 타이틀
  - 2~3줄, 한 줄 9자 안팎
  - 강조 단어 하나만 `[ ]`로 감싼다.
  - 첫 장은 첫 3초 훅이다. 결과나 숫자로 시작하고 인사로 시작하지 않는다.
- 블록
  - 장마다 1개, 많아야 2개
  - 숫자가 있으면 `tiles`나 `hero`, 절차는 `table`, 변화는 `compare`, 연혁은 `timeline`을 쓴다.
- 출처 태그
  - news 장에는 `source`를 반드시 넣는다.
  - 라피치 장 중 하나에 "※ 위 사례와는 별개의 라피치 프로젝트입니다" 같은 구분 문구를 넣는다.
- 카드뉴스에서 뺄 장에는 `"in_cards": false`를 넣는다(카드뉴스 6~8장).
- `meta.status`는 `"draft"`로 둔다.

## 5. caption.md
- 인스타 캡션: 첫 줄 훅, 본문 4~6줄, CTA, 해시태그 10~14개
- 유튜브 숏츠: 제목과 설명
- 타사명, 고객사명 금지

## 6. 빌드와 자가 점검
```
python3 -m engine.build content/NN-slug --cards   # 먼저 빠르게
```
- `out/review_shorts.jpg`, `out/review_cards.jpg`를 Read로 직접 보고 확인한다.
  - 넘침, 깨진 글자, 너무 긴 줄, 강조 위치
- 문제가 있으면 spec을 고친다. `check.txt`에 FAIL이 0개가 될 때까지 반복한다.
- 그다음 전체 빌드(약 2분)를 돌린다.
```
python3 -m engine.build content/NN-slug
```
- 영상의 장 전환부 프레임을 몇 장 뽑아 애니메이션을 확인한다.

## 7. 검수 요청 (여기서 멈춘다)
- `meta.status`를 `"review"`로 바꾸고 커밋, 푸시한다.
- 사용자에게 보여 줄 것
  - 검수 이미지 2장(파일로 전송)
  - check.txt 요약
  - 블로그 제목과 소제목
  - 확인이 필요한 점(추정이 들어간 문장, 홍보 동의가 필요한 고객 사례 등)
- 수정 요청이 오면 고치고 다시 빌드해서 다시 보여 준다.
- 사용자가 명시적으로 승인했을 때만 다음을 한다.
  - `status`를 `"approved"`로 바꾼다.
  - `topics_log.md`의 상태를 "승인"으로 바꾼다.
- **게시는 하지 않는다.** 게시는 사용자가 직접 한다.
